# 好 Prompt vs 差 Prompt 示例 (dg-tools 特化)

> 源自 [agent-coding-playbook/examples](https://github.com/bravekingzhang/agent-coding-playbook)。
> 模糊的 Prompt 会让 AI Agent 猜测——猜测会导致广泛的 diff、意外的行为变更和虚假的信心。

---

## ❌ 差 Prompt 示例

### 示例 1: "修复 DocHandler 的 bug"

```
帮我把 DocHandler 修一下，有个 bug。
```

问题：
- 没有描述当前行为
- 没有描述期望行为
- 没有错误信息或堆栈
- 没有范围界定
- 没有验证方式

### 示例 2: "重构这个模块让它更清晰"

```
重构 extract/excel 下的代码，让它更干净一些。
```

问题：
- "更干净"是未定义的
- Agent 可能重写无关代码
- Agent 可能引入不必要的抽象
- 无法知道何时完成

### 示例 3: "优化性能"

```
PDF 提取太慢了，帮我优化一下。
```

问题：
- 没有度量指标
- 没有基线数据
- 没有目标值
- 没有受影响的代码路径
- 没有验证方法

## ✅ 好 Prompt 示例

### 示例 1: Bug Fix — ExcelHandler 合并单元格处理

```markdown
## Goal
修复 ExcelHandler 在处理含跨行合并单元格的表头时，表头文字丢失的问题。

## Context
- 当前行为: 当表头所在列有 merge cell (如 A1:B1 合并)，extractTableHeaders() 只取第一个 cell 的值，第二列标题丢失
- 期望行为: 所有合并过的列都应该填充正确的表头文字（MergeCellResolver 已经做了矩形化）
- 相关文件: handler/ExcelHandler.java 的 extractTableHeaders() 方法，约第 210 行
- 已有测试: ExcelHandlerExtraTest.testMergedHeader_shouldRetainAllLabels — 目前失败

## Scope
- 仅修改 handler/ExcelHandler.java 中的 extractTableHeaders() 方法
- 可使用 MergeCellResolver 已有的矩形化能力

## Do Not Change
- 不修改 MergeCellResolver.java（它已正确实现）
- 不改变 extract() 方法的 InputStream 签名
- 不引入新的 Maven 依赖

## Verification
- mvn test -Dtest=ExcelHandlerExtraTest#testMergedHeader_shouldRetainAllLabels
- 手动用含跨行列头合并的 .xlsx 文件验证

## Risk
低风险 — 仅修改一个私有方法的内部逻辑
```

### 示例 2: 小重构 — 消除重复错误日志

```markdown
## Goal
消除 DocxHandler / DocHandler / PdfHandler 中重复的错误日志代码，提取为统一工具方法。

## Context
- 三个 Handler 的 extract() 方法 catch 块中都有类似的 `log.error("Extract failed: {}", e.getMessage(), e)` 
- 模式完全相同，只是类名不同

## Scope
- 新增: utils/ExtractionLogger.java（静态工具类）
- 修改: DocxHandler.java, DocHandler.java, PdfHandler.java 的 catch 块

## Do Not Change
- 不改写业务逻辑
- 不改变日志输出格式
- 不修改 ZipHandler / ImageHandler（它们目前没有错误日志）

## Verification
- mvn test — 全部测试通过
- 确认日志输出格式不变

## Risk
低风险 — 纯工具类提取，不改变任何行为
```

### 示例 3: Code Review 请求

```markdown
Review this PR as if it was generated by an AI coding agent.

Context: This PR adds a new ImageHandler to support .png/.jpg/.gif extraction.
SPEC reference: §6.3 ImageHandler

Focus on:
- 是否符合 SPEC.md §6.3 的要求？
- 有无无关改动？
- 内存安全（是否流式读取？）
- 测试覆盖是否充分？
- 是否有过度设计？

Output format:
- Summary
- SPEC Compliance
- Main risks
- Required changes
- Suggested improvements
- Verification gaps
```

## Prompt 结构模板（万能公式）

```markdown
Goal:
- [要实现什么]
- [期望行为]

Context:
- [当前行为是什么]
- [涉及哪些文件/方法]
- [已有的相关代码/模式]

Scope:
- [可以改什么]
- [不能碰什么]

Do Not Change:
- [不可破坏的现有行为]

Verification:
- [mvn test -Dtest=...]
- [手动验证步骤]

Risk:
- [低/中/高 + 理由]
```
