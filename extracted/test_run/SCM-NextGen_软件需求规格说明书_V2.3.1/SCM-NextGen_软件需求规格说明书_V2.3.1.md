# POS: 16 | TYPE: paragraph
1.2 项目背景

# POS: 17 | TYPE: paragraph
随着公司业务的快速扩张，传统的人工+Excel模式的供应链管理已无法满足日均10万+订单的处理需求。现有系统存在以下核心痛点：库存数据滞后（T+1更新）、采购决策依赖经验判断、订单履约周期长（平均72小时）、缺乏全链路可视化监控。这些问题导致库存周转率低（仅4.2次/年）、缺货率高达8.5%、客户投诉率持续上升。

# POS: 18 | TYPE: paragraph
SCM-NextGen项目旨在构建一套覆盖采购、库存、预测、履约、分析五大核心域的智能供应链管理平台。系统引入机器学习算法进行需求预测，结合动态安全库存策略，目标将库存周转率提升至8.0次/年，缺货率降低至2%以下，订单履约周期缩短至24小时以内。 项目预算为人民币1,200万元，计划工期12个月。

2. 总体描述

# POS: 33 | TYPE: paragraph
2.1 产品愿景

# POS: 34 | TYPE: paragraph
SCM-NextGen 的愿景是 成为行业内领先的智能供应链管理平台，通过数据驱动决策、算法赋能运营，实现 供应链全链路 的透明化、智能化和自动化。系统将作为公司数字化转型的核心基础设施，支撑未来3-5年业务规模10倍增长的战略目标。

# POS: 35 | TYPE: paragraph
产品愿景遵循 以下核心设计原则：

# POS: 36 | TYPE: paragraph
智能化（Intelligent）： 利用机器学习、运筹优化等算法技术，替代人工经验决策，实现采购计划、库存策略、路由规划的自动优化。

# POS: 37 | TYPE: paragraph
实时化（Real-time）： 基于流式计算架构，实现库存状态、订单进度、物流轨迹的秒级更新与全链路可视化。

# POS: 38 | TYPE: paragraph
协同化（Collaborative）： 打通供应商、仓库、物流承运商、销售渠道的数据壁垒，构建多方协同的供应链生态网络。

# POS: 39 | TYPE: paragraph
可扩展化（Scalable）： 采用 微服务 架构和云原生技术，支持业务量的弹性伸缩和功能模块的快速迭代。

# POS: 40 | TYPE: paragraph
安全合规（Secure  & Compliant）： 满足等保2.0三级要求，符合《数据安全法》和《个人信息保护法》的相关规定。

# POS: 95 | TYPE: paragraph
3.3.3 库存计算公式

# POS: 96 | TYPE: paragraph
系统核心库存计算逻辑如下：

# POS: 97 | TYPE: table
| 指标名称 | 计算公式 |
| --- | --- |
| 可用库存 | 可用库存 = 在库数量 - 已分配数量 - 冻结数量 - 近效期锁定数量 |
| 在途库存 | 在途库存 = Σ(已发货未入库的调拨单数量) + Σ(供应商已发货未到货的PO数量) |
| 安全库存 | 安全库存 = Z × σ_L × √(LT)，其中Z为服务水平系数，σ_L为需求标准差，LT为提前期 |
| 再订货点 | ROP = 平均日需求 × 提前期 + 安全库存 |
| 库存周转率 | 库存周转率 = 销售成本 / 平均库存金额，平均库存 = (期初库存 + 期末库存) / 2 |
| 库存天数 | 库存天数 = 平均库存数量 / 平均日销售数量 |
