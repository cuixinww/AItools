1. 项目概览

本项目是一个 AI 驱动的需求文档解析与检核系统，当前实现了 Phase 1 提取层（Java）。 核心能力：对复杂嵌套的 UR/FS 需求文档（.docx → .xlsx / .pdf / .doc / .zip / 图片 → 更深层）进行全量无损提取， 将内容展开为平级目录结构（body.md + chunks + data/CSV + media/图片），为后续 AI Agent 层提供结构化的检索基础。

当前版本为 v5，提取层已完整实现。AI 检核层（Phase 2，MapReduce 架构）已设计但尚未编码。

3.5 核心服务类

PositionTracker extractor/PositionTracker.java

使用 Deque<Integer> 栈结构追踪当前递归层级和父级 position。

方法作用
enterEmbedding(parentPosition)入栈 + depth++（进入子文档）
exitEmbedding()出栈 + depth--（回到父文档）
getCurrentLevel()返回当前深度（0 = 根文档）
reset()清空栈，depth = 0

TypeDetector extractor/TypeDetector.java

基于 Apache Tika 从 byte[] 检测真实文件类型。优先级：

  1. Tika MIME 检测 → 查 MIME_TO_EXTENSION 映射表
  2. MIME 为 octet-stream/text/zip 时 → 优先信任文件后缀
  3. Tika 自有 extension 映射
  4. fallback 到文件后缀（hintFileName）

OleExtractor extractor/OleExtractor.java

静态工具类。解包 OLE 二进制对象（Office 嵌入的 native 对象）。

  1. 尝试 POIFSFileSystem 解析为 OLE2 容器
  2. 查找 Ole10Native 流 → 提取原始文件名+内容
  3. 若无 Ole10Native，遍历所有 DocumentNode 提取
  4. 若 OLE2 容器解析失败，尝试裸 Ole10Native 格式

6. OleExtractor 详解

OleExtractor 是项目中技术复杂度最高的模块，专门处理 Office 文档中的 OLE 嵌入对象（如 docx 中嵌入的 xlsx 文件）。

处理流程

OleExtractor.extract(oleData)
│
├── doExtract(oleData)                                       ← 尝试 OLE2 容器解析
│   ├── new POIFSFileSystem(new ByteArrayInputStream(oleData))
│   │   └── fs.getRoot() → DirectoryNode
│   │
│   ├── extractOle10Entries(root, result)                    ← 查找 Ole10Native 流
│   │   ├── 遍历 DirectoryNode 下所有 Entry
│   │   ├── if DocumentNode → DocumentInputStream.readAllBytes()
│   │   ├── tryExtractOle10NativeName(data)                 ← 解析文件名（null-terminated ASCII）
│   │   ├── tryExtractOle10NativeContent(data)               ← 解析内容（4-byte length prefix + data）
│   │   └── if subDir → 递归 extractOle10Entries()
│   │
